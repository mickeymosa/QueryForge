# QueryForge v0.4 — Visual Analytics Studio, ETL lane and grounded advisor

**Status:** Draft feature PR [#25](https://github.com/mickeymosa/QueryForge/pull/25). **No approval or merge.**  
**Parent:** v0.3 draft branch and PR #21.  
**Local operation only:** There is no user authentication or dataset authorization, so do not expose to the public Internet or upload sensitive data.

## 1. The difference between the vision and what is implemented

**Implemented now:**
- A responsive Analytics Studio at `/analytics.html?dataset={id}`.
- C# deterministic chart engine: category counts, numeric distributions, and sum by category.
- Data-backed chart recommendations inferred from bounded column statistics.
- Choice of column, chart type, top N, numeric measure and exclusion of flagged rows.
- SVG browser charts built only from validated backend aggregations; inspectable chart values and JSON export.
- Downloadable evidence report JSON and printable report view (browser Print / Save as PDF).
- Read-only quality advisor and an ETL planner that **previews** the impact of proposed steps.
- Live **linear** ETL flow lane with clickable nodes tied to actual ordered steps.
- Unit tests and Docker HTTP smoke tests.

**Not implemented now:**
- A full draggable, branching, executable DAG with joins and parallel branches.
- Chart/dashboard persistence, time-series modeling, semantic relationships or multi-user sharing.
- A connected language model or autonomous AI agent.
- Production authentication, authorization, migrations, background execution and secrets management.
- Feature equivalence with Power BI, SSIS or SSAS.

## 2. Why calculations happen in C# rather than JavaScript or an LLM

The deterministic `DetermininisticDataInsightsService` (actual class: `DeterministicDataInsightsService`) receives a stored dataset and chart configuration, enforces a typed schema, chooses rows according to the quality policy, parses numeric values under invariant culture and constructs chart points. The frontend is **presentation-only**: it draws the returned values as SVG, with a data table that lets a reviewer verify the result.

- Chart kinds: `CountByCategory`, `SumByCategory`, `Histogram`.
- Chart definitions are typed: `ChartKind`, `ChartRequest`, `ChartPoint`, `ChartResult`.
- Only existing exact header names are accepted.
- `TopN` is bounded to 1–20 (histogram buckets bounded to 2–12).
- All flagged rows are excluded by default, including warnings; users can explicitly change that. The response reports excluded and nonnumeric counts.
- Mixed/missing currencies are rejected before sum aggregations if currency column exists. No conversion is invented.
- Chart outputs include the source dataset SHA-256 for traceability.

**Semantic caveat:** A quality score means percent of rows with no issues according to *currently enabled checks*. This is not a universal measure of real data correctness. For now, date/time analytics, business measure metadata, row-level permissions and user-approved currency policies are missing.

## 3. New HTTP endpoints

| Method | Route | Purpose | Mutation |
| --- | --- | --- | --- |
| GET | `/api/datasets/{id}/insights` | Quality KPI, issue groups, recommended charts | None |
| POST | `/api/datasets/{id}/charts/preview` | Calculate chart points from a typed configuration | None |
| GET | `/api/datasets/{id}/advisor/report` | Evidence-backed executive narrative, suggested ETL steps | None |
| GET | `/api/datasets/{id}/advisor/workflow` | Preview effect of independent suggested ETL steps | None |

**Example chart request:**

```json
{
  "kind": "CountByCategory",
  "column": "currency",
  "topN": 8,
  "excludeFlaggedRows": false
}
```

**Example sum request:**

```json
{
  "kind": "SumByCategory",
  "column": "region",
  "measure": "amount",
  "topN": 8,
  "excludeFlaggedRows": true
}
```

A chart request to sum mixed currencies will return a 400 error rather than an invalid total.

## 4. Reporting and the future agentic architecture

Current `ReadOnlyEtlAdvisor` is deliberately **not AI**. It orchestrates deterministic steps: inspect quality → select safe rule-based suggestions → run ETL preview on a copy → calculate changes → return evidence and warnings. Suggestions are evaluated independently and none is applied. `UsesExternalAi = false`; `HumanApprovalRequired = true`.

A later `IAgentPlanner` can use an explicitly configured LLM to propose valid operations and explain results, subject to structured JSON schemas, data-minimization, prompt-injection defenses, evaluation tests, model/provider selection, cost caps and opt-in. Human approval remains mandatory for all data changes.

A report JSON includes: source dataset ID/hash, whether AI was enabled, evidence records, executive narrative, recommended steps, and human decisions. The browser also offers Print/Save PDF. It is a local printable report, not a signed enterprise audit report.

Next issue: [#26 Agentic AI ETL and evidence-backed reporting](https://github.com/mickeymosa/QueryForge/issues/26).

## 5. Visual ETL lane

`etl.html` renders a live, clickable, keyboard-accessible sequence:
`CSV Source → [step 1] → [step 2] → ... → Revalidate → Save version`.

Click a step to focus its settings. The existing up/down controls reorder the actual steps. The diagram updates through `MutationObserver`. This is **not** a drag-and-drop DAG; non-linear branches will require a graph definition, type checking, and a different execution planner.

## 7. Local walkthrough

```powershell
git fetch origin
git switch --track origin/feat/visual-analytics-agent-planning-v0.4
docker compose up --build -d
docker compose ps
```

Open `http://127.0.0.1:5080` and choose **Try an example**. Open **Analytics Studio**, try category and numeric charts, toggle exclusion policy, inspect the source-backed table and export the report. Open **Prepare and clean this dataset**, use Advanced ETL, reorder steps, preview/apply a new version, and visit the Analytics Studio for that derived dataset.

If already on the v0.4 branch use `git switch feat/visual-analytics-agent-planning-v0.4` and `git pull --ff-only`.

## 8. Release gates

Do not merge this stacked PR until the maintainer reviews actual Windows/Docker browser behavior, chart semantics and user-facing copy. In addition, broader product blockers from parent PRs remain: authentication, dataset ownership, migrations, schema policies, streaming scalability, robust ETL editor, browser E2E, and public deployment safety.

CI confirms build/tests and *selected* HTTP flows, not equivalence to Power BI, enterprise audit compliance, or autonomous AI correctness.
