# Contributing to QueryForge

This is an early-stage, learning-led open-source project. Good first contributions include documentation, tests, reproducible bug reports, architecture critiques and small, scoped features.

## Workflow

1. Search for a relevant issue; discuss large changes before implementing.
2. Branch from `main` using `feat/<topic>`, `fix/<topic>` or `docs/<topic>`.
3. Write a failing test when changing behavior, then implement the smallest solution.
4. Keep pull requests focused. Explain why the change is needed and what could go wrong.
5. Document how you tested; include screenshots for UI changes when appropriate.
6. Never include credentials, customer data or confidential material.

## Definition of Done

- Acceptance criteria met, including negative and edge cases.
- Automated tests added or a documented reason for no test.
- Documentation updated where behavior or architecture changed.
- Security and data-isolation implications considered.
- Author can explain the implementation and its tradeoffs.

We welcome respectful technical disagreement backed by examples and evidence.
